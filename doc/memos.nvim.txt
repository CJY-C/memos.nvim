INTRODUCTION                                           *memos.nvim-introduction*

memos.nvim is a small Neovim client for Memos. It keeps the core path focused
on listing memos, creating memos, editing memos, and saving memo content.

Only the latest Memos /api/v1 API shape is supported. Older API compatibility,
templates, metadata editing, relations, attachments, delete flows, and fuzzy
search are intentionally outside the core implementation.

==============================================================================
COMMANDS                                                   *memos.nvim-commands*

*:Memos*
  Toggle the memo list.

*:MemosCreate*
  Open a new memo buffer.

*:MemosSave*
  Save the current memo buffer. This command is available in memo buffers.

==============================================================================
KEYMAPS                                                     *memos.nvim-keymaps*

Global keymaps are intentionally not created by the plugin. Configure them in
your plugin manager or nixvim, for example `<leader>mm` -> `:Memos`.

List buffer:
>
  <CR>           Edit selected memo
  o              Edit selected memo in a horizontal split
  v              Edit selected memo in a vertical split
  a              Create memo
  s              Search/filter memos on the server
  y              Copy selected memo ID
  r              Refresh list
  .              Load next page
  q              Quit list
<

Memo buffer:
>
  <leader>ms     Save memo
  <Esc>          Return to list
<

==============================================================================
CONFIGURATION                                       *memos.nvim-configuration*

Example:
>
  require("memos").setup({
    host = "http://127.0.0.1:5230",
    token = "your-token",
    env_file = nil,
    page_size = 50,
    list_state = "NORMAL",
    list_order_by = "pinned desc, update_time desc",
    auto_save = false,
    window = {
      enable_float = true,
      width = 0.85,
      height = 0.85,
      border = "rounded",
    },
    keymaps = {
      list = {
        add_memo = "a",
        edit_memo = "<CR>",
        edit_memo_split = "o",
        edit_memo_vsplit = "v",
        search_memos = "s",
        copy_memo_id = "y",
        refresh_list = "r",
        next_page = ".",
        quit = "q",
      },
      buffer = {
        save = "<leader>ms",
        back_to_list = "<Esc>",
      },
    },
  })
<

List search uses the Memos server-side filter parameter and issues one list
request per search. Plain text becomes content.contains("..."), #tag becomes a
tag filter, and raw CEL filter expressions are passed through. Empty search
input clears the filter. It does not fetch extra pages for local fuzzy search.

Copying a memo ID uses the memo resource name already present in the list
response, such as memos/abc123. It does not issue any API request.

Split editing also uses the memo content already present in the list response.
It does not issue any extra API request.

Credentials may also come from a systemd-style env file:
>
  require("memos").setup({
    env_file = "/run/secrets-rendered/memos.env",
  })
<

The file should contain:
>
  MEMOS_HOST=http://127.0.0.1:5230
  MEMOS_TOKEN=your-token
<

MEMOS_HOST must include http:// or https://.

Credential priority is explicit host/token, then env_file, then MEMOS_HOST and
MEMOS_TOKEN. The plugin does not persist accounts. Global shell environment
variables work for temporary debugging, but are not recommended for long-lived
use.

For nixvim, keep secrets out of the Nix store and point the plugin at a runtime
env file:
>
  {
    extraPlugins = [
      pkgs.vimPlugins.plenary-nvim
      # Add memos.nvim through your local plugin package or overlay.
    ];

    extraConfigLua = ''
      require("memos").setup({
        env_file = "/run/secrets-rendered/memos.env",
      })
    '';

    keymaps = [
      {
        mode = "n";
        key = "<leader>mm";
        action = "<cmd>Memos<CR>";
        options.desc = "Open Memos list";
      }
    ];
  }
<

Do not put MEMOS_TOKEN directly in Nix/nixvim config; it may enter the Nix
store. The env file must be readable by the user running Neovim.

With Nix/sops, a template such as `sops.templates."memos.env"` only generates a
secret env file. It does not enter your interactive shell automatically. Use it
from a service with:
>
  systemd.services.<service>.serviceConfig.EnvironmentFile =
    config.sops.templates."memos.env".path;
<

LATENCY TEST                                             *memos.nvim-latency*

Run:
>
  MEMOS_ENV_FILE=/run/secrets-rendered/memos.env ./scripts/latency-test.sh
  ./scripts/latency-test.sh --env-file /run/secrets-rendered/memos.env
  ./scripts/latency-test.sh --env-file /run/secrets-rendered/memos.env --skip-write --runs 5
  ./scripts/latency-test.sh --env-file /run/secrets-rendered/memos.env --page-size 1 --warmup
  ./scripts/latency-test.sh --env-file /run/secrets-rendered/memos.env --skip-write --order-by "create_time desc"
  ./scripts/latency-test.sh --env-file /run/secrets-rendered/memos.env --skip-write --filter 'content.contains("todo")'
  ./scripts/cold-order-by-test.sh --env-file /run/secrets-rendered/memos.env
<

The latency script uses a real Memos API and records list/create/update timing
plus request count and curl timing details. It can also use credentials
injected by a systemd service. It creates and updates a test memo unless
--skip-write is used.

Useful flags:
>
  --runs N        Run multiple rounds
  --page-size N   Compare list latency for different page sizes
  --order-by V    Compare list latency for different server-side sorting
  --filter V      Compare list latency with a Memos CEL server-side filter
  --skip-write    Only measure list requests
  --warmup        Run a lightweight auth request before measured requests
<

If connect time is high, inspect network/proxy path. If time to first byte is
high while connect is low, inspect Memos server or database work.

`scripts/cold-order-by-test.sh` runs list-only tests for several orderBy values
and sleeps 30 minutes between them by default. Use `--sleep-seconds N` for a
shorter local check.

Server-side list keepalive~

If connect time is low but time to first byte is high, the slow part is likely
the Memos server or database handling the list request. In that case, keep the
real list path warm from systemd or the server, not from the plugin.
>
  curl -fsS \
    --max-time 300 \
    --write-out "warmup http=%{http_code} total=%{time_total} connect=%{time_connect} ttfb=%{time_starttransfer}\n" \
    -H "Authorization: Bearer $MEMOS_TOKEN" \
    "$MEMOS_HOST/api/v1/memos?pageSize=1&state=NORMAL&orderBy=update_time%20desc" \
    >/dev/null
<

For NixOS/systemd, run the keepalive from a service using the same secret env
file:
>
  systemd.services.memos-list-keepalive = {
    serviceConfig = {
      Type = "oneshot";
      EnvironmentFile = config.sops.templates."memos.env".path;
      ExecStart = "${pkgs.curl}/bin/curl -fsS --max-time 300 --output /dev/null --write-out \"warmup http=%%{http_code} total=%%{time_total} connect=%%{time_connect} ttfb=%%{time_starttransfer}\\n\" -H \"Authorization: Bearer $MEMOS_TOKEN\" \"$MEMOS_HOST/api/v1/memos?pageSize=1&state=NORMAL&orderBy=update_time%20desc\"";
    };
  };

  systemd.timers.memos-list-keepalive = {
    wantedBy = [ "timers.target" ];
    timerConfig = {
      OnBootSec = "2min";
      OnUnitActiveSec = "1min";
      AccuracySec = "10s";
    };
  };
<

`pageSize=1` is enough to exercise the list path. Start with a short interval
such as 1 minute and inspect the ttfb values in journalctl; if the list path
stays hot, gradually relax the timer to 2 minutes, 5 minutes, or longer. The
plugin does not run this keepalive itself, so the default request model stays
explicit and minimal.
