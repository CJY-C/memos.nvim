INTRODUCTION                                           *memos.nvim-introduction*

memos.nvim is a small Neovim client for Memos. It keeps the core path focused
on listing memos, creating memos, editing memos, and saving memo content.

Only the latest Memos /api/v1 API shape is supported. Older API compatibility,
templates, metadata editing, relations, attachments, delete flows, and fuzzy
search are intentionally outside the core implementation.

==============================================================================
COMMANDS                                                   *memos.nvim-commands*

*:Memos*
  Toggle the memo list.

*:MemosCreate*
  Open a new memo buffer.

*:MemosSave*
  Save the current memo buffer. This command is available in memo buffers.

*:MemosSwitch*
  Switch the active saved Memos account.

*:MemosUserAdd*
  Add a saved Memos account.

*:MemosUserDelete*
  Delete a saved Memos account.

==============================================================================
KEYMAPS                                                     *memos.nvim-keymaps*

Global:
>
  <leader>mm     Toggle memo list
<

List buffer:
>
  <CR>           Edit selected memo
  a              Create memo
  r              Refresh list
  .              Load next page
  q              Quit list
<

Memo buffer:
>
  <leader>ms     Save memo
  <Esc>          Return to list
<

CONFIGURATION                                       *memos.nvim-configuration*

Example:
>
  require("memos").setup({
    host = "http://127.0.0.1:5230",
    token = "your-token",
    env_file = nil,
    page_size = 50,
    list_state = "NORMAL",
    list_order_by = "pinned desc, update_time desc",
    auto_save = false,
    window = {
      enable_float = true,
      width = 0.85,
      height = 0.85,
      border = "rounded",
    },
  })
<

Credentials may also come from a systemd-style env file:
>
  require("memos").setup({
    env_file = "/run/secrets-rendered/memos.env",
  })
<

The file should contain:
>
  MEMOS_HOST=http://127.0.0.1:5230
  MEMOS_TOKEN=your-token
<

MEMOS_HOST must include http:// or https://.

Credential priority is explicit host/token, then env_file, then MEMOS_HOST and
MEMOS_TOKEN, then saved accounts. Global shell environment variables work for
temporary debugging, but are not recommended for long-lived use.

With Nix/sops, a template such as `sops.templates."memos.env"` only generates a
secret env file. It does not enter your interactive shell automatically. Use it
from a service with:
>
  systemd.services.<service>.serviceConfig.EnvironmentFile =
    config.sops.templates."memos.env".path;
<

LATENCY TEST                                             *memos.nvim-latency*

Run:
>
  MEMOS_ENV_FILE=/run/secrets-rendered/memos.env ./scripts/latency-test.sh
  ./scripts/latency-test.sh --env-file /run/secrets-rendered/memos.env
  ./scripts/latency-test.sh --env-file /run/secrets-rendered/memos.env --skip-write --runs 5
  ./scripts/latency-test.sh --env-file /run/secrets-rendered/memos.env --page-size 1 --warmup
  ./scripts/latency-test.sh --env-file /run/secrets-rendered/memos.env --skip-write --order-by "create_time desc"
  ./scripts/cold-order-by-test.sh --env-file /run/secrets-rendered/memos.env
<

The latency script uses a real Memos API and records list/create/update timing
plus request count and curl timing details. It can also use saved accounts or
credentials injected by a systemd service. It creates and updates a test memo
unless --skip-write is used.

Useful flags:
>
  --runs N        Run multiple rounds
  --page-size N   Compare list latency for different page sizes
  --order-by V    Compare list latency for different server-side sorting
  --skip-write    Only measure list requests
  --warmup        Run a lightweight auth request before measured requests
<

If connect time is high, inspect network/proxy path. If time to first byte is
high while connect is low, inspect Memos server or database work.

`scripts/cold-order-by-test.sh` runs list-only tests for several orderBy values
and sleeps 30 minutes between them by default. Use `--sleep-seconds N` for a
shorter local check.
